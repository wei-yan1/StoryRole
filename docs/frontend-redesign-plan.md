# StoryRole 书架优先前端重做计划

## 1. 产品方向

这一版不再做“通用聊天优先”的首页，而是按用户的真实使用顺序组织：

```text
先选一本小说 → 进入小说页 → 从这本书的角色开始对话
新建小说时：导入小说原文 → 回到书架 → 继续整理角色
```

首页必须是一眼能看懂的书架；聊天、角色、工具是用得上的二级能力，不是产品入口。整体视觉从“档案工具 / 聊天软件”改成纸张、书脊、深绿与砖红的阅读空间，但不依赖任何《三体》专属素材。

## 2. 改造前盘点

旧 `/library` 页面只有一个 `three_body` 资料行和大面积留白，用户看不出“这是一本书”，也看不出下一步该点哪里。旧 `/settings` 暴露“对话模型 / 路由模型”两个输入框，但两者并不是用户需要理解的业务概念。旧 `/usage` 把不同任务的调用混在一个表格里，看不出对话、场景、人设、工具分别花了多少。旧前端页面分割不彻底，仍像一个被拆开的工作台。

## 3. 信息架构

### 3.1 一级导航

| 顺序 | 导航 | 路由 | 职责 |
|---|---|---|---|
| 1 | 书架 | `/`、`/novels`、`/library` | 产品首页，小说封面网格与最近继续 |
| 2 | 对话 | `/chats` | 已开始的对话收件箱，二级入口 |
| 3 | 角色 | `/characters` | 跨小说的角色名册与筛选 |
| 4 | 工具 | `/tools` | 图片、OCR、图片理解、语音、翻译 |
| 5 | 用量 | `/usage` | 按任务环节统计模型调用 |
| 6 | 设置 | `/settings` | 账户、运行模型、模型接入、运行参数、密钥 |

### 3.2 页面路由

| 路由 | 页面职责 |
|---|---|
| `/login` | 登录 / 注册；不再出现三体角色示例 |
| `/` | 书架：书封网格、搜索、新增小说、最近继续、怎么开始 |
| `/novels` | 与 `/` 相同的书架入口 |
| `/novels/new` | 新增小说：书名、拖拽文件、导入说明、文件建议 |
| `/novels/{slug}` | 小说详情：书封、简介、角色统计、cast 网格、最近对话 |
| `/characters` | 角色名册，按小说筛选 |
| `/characters/new?source=...` | 从指定小说创建角色 |
| `/characters/{id}` | 角色主页：人设摘要、场景、开始对话 |
| `/characters/{id}/scenes` | 场景时间线与人设生成 |
| `/chats` | 对话收件箱 |
| `/chats/new?character=...` | 从角色开始新对话 |
| `/chats/{thread_id}` | 单条会话与 SSE 流式回复 |
| `/tools`、`/tools/*` | 多模态工具入口与独立工具页 |
| `/usage` | 用量总览、任务环节、趋势、细分操作、最近调用 |
| `/settings` | 账户、当前运行模型、模型接入、运行参数、服务密钥 |

小说地址使用由书名生成的可读 slug，例如 `/novels/三体-三部曲`；slug 不存在或重名时回退 `novel_id`。`/library` 兼容到书架。

## 4. 页面设计

### 书架

- 封面网格是视觉主体；用书名哈希生成确定性配色、书脊、书名和首字标记，不依赖外部图片。
- 第一张卡是小说，第二张是“新增一本小说”虚线卡；导入后自动出现在书架。
- 书目下方是最近继续，右侧只保留“怎么开始”和“导入另一本”两个短模块，避免右侧栏堆信息。
- 1440 下是 4 列书封，768 收紧，390 变 2 列；不出现横向溢出。

### 小说详情

- 封面 + 标题 + 来源 + 状态，四个统计：角色、场景、对话、可对话角色。
- 角色卡整卡可点进角色主页；卡内另有“进入角色 / 开始对话”按钮。
- 角色卡展示摘要、提及次数、场景数量和最新人设版本；没有角色时给出明确的添加入口。
- 底部是“最近在这本书里发生”，把对话放回小说上下文。

### 新增小说

- 书名输入、拖拽区、文件列表、导入按钮。
- 右侧“导入之后”三步解释后台会做什么。
- 下方“导入前看一眼”补充文件粒度、章节标题、UTF-8 三条实际建议，填满页面而不制造无意义留白。
- 自动从文件名填书名；仅接受 `.txt`、`.md`、`.markdown`。

### 用量

- 顶部四个总览：调用数、Token、费用、P95 延迟。
- “按任务环节”卡片：角色对话、场景分析、人设生成、对话辅助、检索与重排、工具调用、其他。
- “调用趋势”按天； “细分操作”按 agent/operation； “最近调用”只展示具体记录并标注环节。
- 任务归类在后端完成：`_usage_stage` 和 `_aggregate_stages` 在 Python 侧聚合，避免 SQL 中 `LIKE '%'` 与 psycopg 占位符冲突。

### 设置

- 去掉“对话模型 / 路由模型”双输入。
- “当前运行模型”按“对话与检索 / 多模态工具”分组只读展示，角色对话、深度推理、一致性检查、场景重排、检索向量、图片、OCR、图片理解、ASR、TTS、翻译各自一行。
- “模型接入”参考 WeKnora：连接名称、用途、OpenAI 兼容 / Ollama、Base URL、模型 ID、API Key、测试连接、保存连接。
- 服务密钥不回显，显示“已保存（不显示）”或“未设置”；测试接口不保存、不返回 key。
- 自定义连接目前只保存为当前账号的连接定义，不会自动改写系统运行模型；页面明确说明这一点，避免用户误以为保存后立即切换核心对话模型。

## 5. 设计系统

- 背景：暖纸色 `#f7f2e7`；侧栏：浅纸张；强调色：深绿 `#33544c` 与砖红 `#9c4b36`。
- 标题：Noto Serif SC；正文：Noto Sans SC / 系统无衬线；数字使用等宽体。
- 216px 侧栏；小圆角、细边框、低阴影；封面和书脊承担视觉重量。
- 头像使用 6 组低调色板，不再随机彩虹色；书封用书名哈希固定配色。
- 响应式：1440 / 768 / 390 三档均已截图检查，无横向溢出。

## 6. 接口与解耦

- 小说：`GET /api/app/novels`、`GET /api/app/novels/{id_or_slug}`、`GET /api/app/characters?novel_id=`、`GET /api/app/conversations?novel_id=`。
- 用量：`GET /api/app/usage?days=` 返回 `totals`、`daily`、`by_stage`、`by_agent`、`recent.stage`。
- 设置：`GET/PUT /api/app/settings`；自定义模型键为 `models.custom.*`；`POST /api/app/models/test` 只测试不存储。
- 前端 API 根地址可通过 `window.APP_API_BASE` 或 `localStorage.storyrole_api_base` 配置，`App.setApiBase()` 可修改；默认同源，便于前后端分开部署。
- 后端模型网关仍由 `OPENAI_BASE_URL` / `OPENAI_API_KEY` 配置；语言模型按项目约束继续使用 `deepseek-v4.1-flash-1017`。

## 7. 验收口径

1. 书架是登录后的默认页；新增小说和“最近继续”都可点。
2. 从书架点一本小说进入小说详情，从角色卡点进角色页，从角色开始新对话。
3. 用量页能按任务环节分开显示，切换 7 / 30 天不报错。
4. 设置页不再出现“对话模型 / 路由模型”输入，当前运行模型为只读单行。
5. 所有新页面在 1440 / 768 / 390 下无横向溢出，无 console / pageerror。
6. 后端 `pytest tests/rolerag -q` 全绿；真实请求返回 200。
